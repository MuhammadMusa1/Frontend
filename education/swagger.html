Инструменты для тестирования API

Добро пожаловать! Сегодня мы простыми словами разберём, что такое API и как его можно тестировать.

API — это как меню в ресторане: вы выбираете блюдо (функцию), делаете заказ (запрос) и получаете еду (ответ).

Что такое API Application Programming Interface — набор правил для общения программ. ?

API — это как официант: вы говорите, что хотите, а он приносит заказ с кухни.

Зачем тестировать API?

  • Чтобы убедиться, что «кухня» готовит правильно.
  • Чтобы официант не перепутал заказы.
  • Чтобы избежать проблем на продакшене.

Основные типы запросов

GET — спросить официанта: «Покажи меню». (Получаем данные)

POST — заказать блюдо: «Принеси пиццу». (Отправляем данные)

PUT — заменить блюдо: «Сделай другой гарнир к мясу». (Обновляем данные)

PATCH — подправить заказ: «Добавь сыр к пицце». (Частичное обновление)

DELETE — отменить блюдо: «Отмени салат». (Удаляем данные)

HEAD — спросить только «какие блюда есть?», без деталей. (Метаданные)

Postman

Postman — приложение для отправки запросов к API и получения ответов.

Пример запроса в Postman

GET https://jsonplaceholder.typicode.com/posts/1

В ответ вы получите данные в формате JSON.

Возможности Postman

  • Сохранять запросы
  • Группировать их в коллекции
  • Автоматизировать тестирование

Swagger

Swagger показывает документацию по API в удобном виде. Это как меню с картинками и описанием.

В Swagger UI видно список запросов (эндпоинтов) и параметры.

Выводы

  • API — это способ общения программ.
  • Тестирование помогает избежать ошибок.
  • Инструменты: Postman и Swagger.
